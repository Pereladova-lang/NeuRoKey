# NeuRoKey — Механики возрастных когорт 7–10 и 15–18 лет (Design)

**Дата:** 3 августа 2026
**Статус:** Approved
**Трек:** 1 из 6 треков механик всего проекта (см. `idea.md`, раздел "Три отдельных трека R&D"). Остальные треки — геймификация на масштаб, гейтинг доступа, компенсаторный слой, родительская экосистема, монетизация — прописываются отдельными спеками.

## Контекст

Пилот (`docs/superpowers/specs/2026-07-15-neurokey-pilot-design.md`) реализует механику только для когорты 11–14 лет: 3 типа упражнений (`comic`, `data`, `robot`), rule-based движок (`src/lib/engine.ts`), 4 когнитивные шкалы (attention, memory, logic, control), геймификация с маскотом и бейджами.

Этот спек расширяет механику на соседние школьные когорты — 7–10 и 15–18 лет — без изменения архитектуры пилота: те же принципы (трёхслойное упражнение, rule-based ротация, 4 шкалы), но контент, параметры сессии и визуальный язык геймификации адаптированы под возраст.

Вне охвата этого спека: 4–6 лет, ВУЗ, профессиональные треки, реальный анализ экранной нагрузки (компенсаторный слой), техническая блокировка контента на устройстве.

## 1. Расширение схемы данных

Расширяет модели `Exercise` и `Child` из пилота (Task 1), не меняя остальные:

```prisma
model Exercise {
  // ...существующие поля из пилота...
  ageCohort   String   // "7-10" | "11-14" | "15-18"
}
```

- Существующие 90 записей пилота при миграции получают `ageCohort = "11-14"`.
- `Child.ageCohort` не хранится отдельным полем в БД — вычисляется из `Child.age` при каждом запросе через чистую функцию:

```ts
export function ageCohortFor(age: number): "7-10" | "11-14" | "15-18" {
  if (age <= 10) return "7-10";
  if (age <= 14) return "11-14";
  return "15-18";
}
```

`Session`, `SessionResult`, `Achievement` не меняются — когорта читается через связь `Session.child.age`.

## 2. Параметры сессии по возрасту

| Параметр | 7–10 | 11–14 (пилот, неизменно) | 15–18 |
|---|---|---|---|
| Упражнений в сессии | 2 | 3 | 3–4 (случайно) |
| Длительность сессии | 2–4 мин | 4–7 мин | 7–12 мин |
| Уровней сложности | 3 | 3 | 3 |
| Правило level-up | 3 подряд >80% на уровне → +1 (как в пилоте) | как в пилоте | как в пилоте |
| Правило level-down | 2 подряд <50% → −1 (мягче, чем в пилоте, из-за случайных ошибок у младших) | 1×<50% → −1 (как есть в пилоте) | 1×<50% → −1 (как в пилоте) |
| Когнитивные шкалы | attention, memory, logic, control (те же 4) | те же 4 | те же 4 + производный UI-лейбл в родительском дашборде "устойчивость к экзаменационному стрессу" = f(control, attention), не отдельная шкала в БД |
| Тон feedback на ошибку | максимально мягкий: без слова "неверно", только "Почти! Давай ещё раз" + подсказка | как в пилоте ("подсказка, повторная попытка, не штраф") | прямая формулировка: "Неверно, вот почему:" — подростки ожидают взрослой честной обратной связи |

Функция `nextLevel` из `engine.ts` параметризуется порогом level-down (аргумент `downThreshold: number` по умолчанию 1, для 7–10 передаётся 2) — обратная совместимость с пилотом сохраняется через дефолт.

## 3. Контент для 7–10 лет

Три типа, 3 уровня × 10 вариантов = 90 записей (симметрично пилоту).

### 3.1 «Ловля рыб» (`fishing`)
- **Академический:** таблица умножения/деления. Уровень 1: ×2–×5; уровень 2: ×2–×9; уровень 3: смешанные примеры с остатком.
- **Когнитивный:** избирательное внимание — ловить только рыб с числами, удовлетворяющими условию, среди рыб-отвлекателей.
- **Компенсаторный (заглушка):** помечается тегом `suitsAfter: "passive_video"` для будущего использования (см. раздел 5).
- **Механика:** сцена с плывущими рыбками-числами, тап по подходящей; неверный тап — рыбка уплывает без штрафа; ограничение раунда по времени, не по числу попыток.

### 3.2 «Поиск лисы» (`find-fox`)
- **Академический:** английская лексика. Уровень 1: 10 базовых слов (животные/цвета); уровень 2: простые фразы-предлоги места ("the fox is behind..."); уровень 3: короткие инструкции на английском.
- **Когнитивный:** рабочая память + планирование (запомнить подсказку → применить на сцене).
- **Компенсаторный (заглушка):** `suitsAfter: "video_switching"`.
- **Механика:** сцена с объектами, текстовая/озвученная подсказка на английском, ребёнок находит объект; 2 подсказки-попытки, затем показ ответа с объяснением.

### 3.3 «Робот на маршруте» (`robot`)
- **Академический:** базовая логика последовательностей действий (без привязки к конкретному предмету).
- **Когнитивный:** планирование + контроль импульсов.
- **Компенсаторный (заглушка):** `suitsAfter: "high_intensity_game"`.
- **Механика:** переиспользует `simulate()` из `src/lib/robot-sim.ts` (пилот, Task 9) без изменений сигнатуры. Поле меньше, чем в пилоте: 4×4 / 5×5 / 6×6 (вместо 5×5 / 6×6 / 7×7 у 11–14), лимит энергии ниже.

## 4. Контент для 15–18 лет

Три типа, 3 уровня × 10 вариантов = 90 записей. Академический контекст — российская школа, формат ОГЭ/ЕГЭ.

### 4.1 «Разбор текста» (`text-analysis`)
- **Академический:** работа с текстом в формате ЕГЭ по русскому/литературе — найти тезис, аргумент, логическую ошибку в рассуждении.
- **Когнитивный:** критическое мышление, аналитическое чтение.
- **Механика:** короткий текст-абзац + вопрос с 4 вариантами ответа (не 3, как у младших — выше толерантность к сложности выбора). Уровень растёт через длину текста и правдоподобность неверных вариантов ("ловушки").

### 4.2 «Разбор данных» (`data-exam`)
- **Академический:** чтение графиков/таблиц в формате заданий ЕГЭ по математике/обществознанию.
- **Когнитивный:** критическое мышление + оценка достоверности вывода.
- **Механика:** переиспользует `BarChart` из `src/components/exercises/BarChart.tsx` (пилот, Task 8) без изменений. Добавляется тип вопроса "недостаточно данных для вывода" как валидный правильный ответ (в пилоте такого типа вопроса не было).

### 4.3 «Планирование и приоритеты» (`planning`)
- **Академический:** без привязки к предмету — тайм-менеджмент/приоритизация в контексте подготовки к экзаменам.
- **Когнитивный:** метапознание, планирование, управление цифровыми привычками — прямое попадание в заявленную цель когорты 15–18 из видения.
- **Механика:** список задач с весами/дедлайнами, ребёнок расставляет порядок или распределяет время между задачами; система сравнивает с оптимальным решением и объясняет разницу. Новый компонент, аналогов в пилоте нет.

## 5. Точка расширения под компенсаторный слой

Реальный анализ экранной нагрузки — предмет отдельного (научного) трека и в этом спеке не проектируется. Закладывается только типовой интерфейс, чтобы будущая интеграция не потребовала переписывания движка:

```ts
// src/lib/exercise-selector.ts — обёртка над pickSessionTypes() из пилота
type LoadSignal = { type: "youtube" | "tiktok" | "game" | "unknown"; minutes: number } | null;

// Сегодня loadSignal всегда null во всех вызовах → поведение идентично
// текущей случайной ротации pickSessionTypes() из пилота. Контент помечен
// полем suitsAfter (разделы 3–4) для будущего маппинга loadSignal → тип.
function pickSessionTypesWithLoad(
  lastFirstType: ExerciseType | null,
  loadSignal: LoadSignal,
): ExerciseType[]
```

`suitsAfter` в контенте 7–10 (раздел 3) — единственное текстовое поле для этого трека; для 15–18 не заводится, т.к. компенсаторная гипотеза сформулирована в видении применительно к младшим когортам (пассивный видеоконтент vs переключение внимания), у подростков типовая нагрузка (соцсети/игры) менее дифференцирована в текущем видении.

## 6. Геймификация для 15–18 лет

Отдельный визуальный язык — без маскота и без детских элементов пилота:

- **Прогресс:** line-chart роста 4 шкал за 4 недели вместо анимированного маскота.
- **Достижения:** текстовые milestone-формулировки ("7 сессий подряд", "Уровень 3 в анализе данных") вместо иконок-бейджей — в стиле трекера привычек, не игровых наклеек.
- **Стрик:** сохраняется как концепт (тот же движок `nextStreak`), но отображается как счётчик дней без иконки-огонька.
- **Тон реплик:** конкретные формулировки с цифрами ("Точность выросла с 68% до 81% за неделю") вместо эмоциональных фраз маскота.
- **Feedback после сессии:** шкала 1–5 или бинарный выбор "полезно / не полезно" вместо эмодзи-палитры (😍😊😐😕) из пилота.

Реализуется отдельным модулем `src/lib/progress-lines.ts` с тем же контрактом, что `src/lib/mascot-lines.ts` из пилота (`getProgressLine(context): string`), но собственным пулом реплик — не заменяет и не модифицирует пилотный `mascot-lines.ts`.

Для 7–10 геймификация пилота (маскот, эмодзи-фидбек, бейджи-наклейки) переиспользуется без изменений — младшая когорта ближе по восприятию к 11–14, чем к 15–18.

## 7. Тестирование

По аналогии с пилотом (`tests/unit/seed-content.test.ts`, `tests/unit/engine.test.ts`):
- Контент-тесты на объём и валидность для новых пулов `fishing`, `find-fox`, `robot` (7–10) и `text-analysis`, `data-exam`, `planning` (15–18) — по образцу существующих тестов пилота.
- Тест `ageCohortFor()` на граничные значения (10/11, 14/15).
- Тест параметризованного `nextLevel(history, current, downThreshold)` — обратная совместимость с существующими тестами пилота (дефолт `downThreshold=1`) плюс новый кейс `downThreshold=2`.
- Тест `progress-lines.ts` по образцу `mascot-lines.test.ts` — каждый контекст возвращает непустую строку из пула ≥3.

## Самопроверка

- **Покрытие:** параметры сессии, контент (6 новых типов упражнений, 180 записей), геймификация, точка расширения под компенсацию, тестирование — для обеих когорт.
- **Совместимость с пилотом:** ни одна существующая модель/функция/тест пилота не меняет поведение по умолчанию; все расширения — новые опциональные параметры или новые файлы.
- **Вне охвата (осознанно):** 4–6 лет, ВУЗ, проф. треки, реальный анализ нагрузки, гейтинг доступа на устройстве, монетизация и родительский дашборд на масштаб — отдельные треки.
