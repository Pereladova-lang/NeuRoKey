# Деплой neurokey-pilot на Railway — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move neurokey-pilot from local-only SQLite dev to a public Railway deployment on managed Postgres, with CI and a documented, repeatable seed/migrate flow.

**Architecture:** Prisma schema switches from `sqlite` to `postgresql` (single provider for both dev and prod — Prisma does not support per-environment providers in one schema). Local dev runs Postgres via Docker Compose instead of a `dev.db` file. Railway hosts two services in one project: the Next.js app (Nixpacks build) and a managed Postgres plugin, wired together via GitHub auto-deploy on push to `main`. A new GitHub Actions workflow runs lint + unit/integration tests on every push/PR as a visibility gate (non-blocking for the Railway deploy itself).

**Tech Stack:** Next.js 15 (App Router), Prisma 6, PostgreSQL 16, Docker Compose (local dev only), Railway (hosting + managed Postgres), GitHub Actions (CI).

## Global Constraints

- Interface language is Russian (UI copy, product docs); code identifiers, comments, and commit messages are English.
- All commands in this plan run from inside `neurokey-pilot/` unless stated otherwise.
- `BILLING_MOCK=1` stays set in every environment touched by this plan (staging/first prod deploy) — real Robokassa keys are explicitly out of scope (see spec §8).
- Never commit `.env` or real secrets; `.env.example` only documents variable names.
- Existing SQLite migrations in `prisma/migrations/` are being replaced, not extended — do not add a new SQLite migration on top of them.

### Task 5: GitHub Actions CI (lint + unit/integration tests)

**Files:**
- Create: `.github/workflows/ci.yml` (repo root, not inside `neurokey-pilot/`)

**Interfaces:**
- Consumes: `neurokey-pilot/package.json` scripts `lint` and the `vitest` devDependency; needs a Postgres service for integration tests that touch the DB.

- [ ] **Step 1: Write the workflow**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: neurokey-pilot
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: neurokey
          POSTGRES_PASSWORD: neurokey_dev
          POSTGRES_DB: neurokey
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U neurokey"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    env:
      DATABASE_URL: "postgresql://neurokey:neurokey_dev@localhost:5432/neurokey"
      AUTH_SECRET: "ci-test-secret"
      BILLING_MOCK: "1"
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"
          cache-dependency-path: neurokey-pilot/package-lock.json
      - run: npm ci
      - run: npx prisma migrate deploy
      - run: npm run lint
      - run: npx vitest run
```

- [ ] **Step 2: Verify locally before pushing**

Run: `docker compose up -d` (from `neurokey-pilot/`, if not already running), then from `neurokey-pilot/`:
`DATABASE_URL="postgresql://neurokey:neurokey_dev@localhost:5432/neurokey" AUTH_SECRET=ci-test-secret BILLING_MOCK=1 npx prisma migrate deploy && npm run lint && npx vitest run`
Expected: all three commands exit 0, mirroring what CI will run.

- [ ] **Step 3: Commit and push**

```bash

git commit -m "ci: add GitHub Actions workflow for lint + tests"
git push
```

- [ ] **Step 4: Confirm the workflow runs on GitHub**
