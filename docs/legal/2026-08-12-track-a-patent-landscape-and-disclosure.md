**Дата:** 12 августа 2026
**Статус:** черновик для передачи патентному поверенному — не является юридическим заключением
**Готовил:** Claude (research assistant), по запросу в рамках трека A (см. `docs/superpowers/specs/2026-08-12-cognitive-profile-skills-platform-design.md`, раздел "Связанные треки")

## Дисклеймер

Этот документ — рабочий материал для подготовки к разговору с патентным поверенным, **не патентный поиск в юридическом смысле** и не заключение о патентоспособности. Веб-поиск покрывает публично индексируемые источники (Google Patents, открытые статьи), не заменяет платный поиск по базам Роспатента (ФИПС) и PCT (WIPO PatentScope) силами специалиста. Перед подачей любой заявки — обязательна проверка регистрированным патентным поверенным (в РФ — аттестован Роспатентом), включая:
- полный поиск по классам МПК (G09B — обучение; G06F — обработка данных; A61B — если возникнут физиологические измерения) в русскоязычной и англоязычной базах;
- проверку формулировок на предмет медицинских claims (см. ограничение из спека когнитивного профиля, раздел 2.4 — критично для избежания требований о регистрации как медизделие);
- решение по стратегии (способ vs. полезная модель vs. только ноу-хау/копирайт на код).

## 1. Что патентуется — 4+ элемента идеи

По итогам уточнения с продукт-оунером, объекты защиты:

1. **Механика гейтинга через нейросессию** — доступ к высокодофаминовому контенту открывается только после прохождения короткой адаптивной нейрокогнитивной сессии.
2. **Алгоритм компенсаторной адаптации** — по паттерну предшествующего экранного поведения определяется вероятный тип когнитивной нагрузки → подбирается упражнение, целенаправленно компенсирующее именно этот тип нагрузки.
3. **Трёхслойная структура упражнения** — одно упражнение одновременно решает академическую, нейрокогнитивную и компенсаторную задачи (не три отдельных упражнения).
4. **Возрастная траектория навыков (4–18+)** — один и тот же когнитивный механизм (напр. тормозный контроль, рабочая память) сопровождает пользователя через все возрастные этапы, меняется только контекст/сложность.
5. **(добавлено из спека `2026-08-12-cognitive-profile-skills-platform-design.md`) Формат `Skill`** — авторская методика компенсации, формализованная как версионируемая структура данных с полями `trigger`, `targetScales`, `exerciseParams`, `authorship`, `citations` — спроектирована одновременно как основа будущей процедурной генерации *и* как история приоритета для патентной заявки (см. раздел 3.3 того спека).
6. **(из того же спека) `CognitiveProfile` / `AssessmentEngine`** — построение цифрового когнитивного профиля из расширяемого набора `SignalSource` (внутриигровое взаимодействие → экранное время устройства → визуальный канал), с baseline-диагностикой и периодической переоценкой.

## 3. Оценка патентоспособности и риски отказа

### 3.1 Общий барьер: РФ — статья 1350 ГК РФ, п.5

В России **программы для ЭВМ, алгоритмы и методы "как таковые" исключены из патентоспособных объектов** (ст. 1350 ГК РФ, п.5). Патент на изобретение ("способ") возможен, только если решение:
- представлено как **технический** способ (последовательность действий над материальным объектом техническими средствами), а не как чисто ментальная/педагогическая процедура;
- даёт **технический результат** (не просто "улучшение усвоения материала" — это не технический эффект в узком смысле практики Роспатента).

Источники: [сводка по патентованию ПО в РФ](https://patentpatentpatent.ru/01-kak-poluchit-patent-na-programmnoe-obespechenie) (см. п.5 ст. 1350 ГК РФ), [обзор патентования способа обучения](https://ezybrand.ru/blog/kak-zashhitit-obrazovatelnuyu-metodiku-ili-sposob-obucheniya/) — упоминает прецедент: патент №2634635 на "способ развития эмоционального интеллекта у детей" **выдан как изобретение**, то есть образовательные методики патентуются в РФ, если сформулированы через конкретные технические/аппаратные шаги (экран, сенсор, вычислительное устройство), а не как чисто содержательная педагогика.

**Практический вывод для NeuroKey:** формулировка заявки должна опираться на **вычислительно-техническую** часть (обработка сигналов взаимодействия с устройством → вычисление профиля → выбор из закодированного набора параметров упражнения по алгоритму), а не на педагогическое содержание задания. Это прямо совпадает с архитектурным решением из спека `Skill`/`CognitiveProfile` — там методика уже отделена как структура данных и алгоритм от контента.

### 3.3 Итоговая рекомендация по объёму заявки (для обсуждения с поверенным, не финальное решение)

Наиболее реалистичная стратегия по открытым данным: **одна широкая заявка на "способ"**, объединяющая элементы 1+2+6 (гейтинг + алгоритм компенсаторной адаптации + построение профиля из сигналов) как единый технический процесс с конкретными вычислительными шагами, а не как отдельные патенты на каждый элемент по отдельности. Элементы 3, 4, 5 (трёхслойная структура, возрастная траектория, формат Skill как данные) — защищать не патентом, а комбинацией: копирайт на код и контент, коммерческая тайна на конкретные пороги/веса (`TYPE_WEIGHTS`, пороги `Skill.trigger`), товарный знак на название методики.

Это резко снижает риск отказа (не пытаемся патентовать неподходящие для патента объекты) и фокусирует бюджет патентного поверенного на одной сильной заявке вместо нескольких слабых.

## 4. Черновик invention disclosure

> Формат ниже — стандартная структура invention disclosure form, которую патентные поверенные используют как отправную точку. Не заявка, а входной материал для неё.

**Название (рабочее):** Способ адаптивного гейтинга доступа к цифровому контенту через нейрокогнитивную компенсаторную сессию

**Изобретатели / вклад:**
_(заполняется по факту — соответствует полю `Contributor` из формата `Skill`: имя, квалификация, роль. Юридическая фиксация долей — отдельный договор, не часть этой формы, см. раздел "Связанные треки" в `2026-08-12-cognitive-profile-skills-platform-design.md`.)_

**Дата первой формулировки идеи:** _(нужно зафиксировать точную дату — важно для приоритета; в коде это можно опереть на git-историю `docs/superpowers/specs/2026-08-12-cognitive-profile-skills-platform-design.md` и `ProjectNeuro.txt`, но лучше независимая фиксация — напр. через нотариальное свидетельствование или депонирование в Роспатенте)_

**Проблема, которую решает изобретение:**
Существующие приложения родительского/самостоятельного контроля экранного времени (Kids360, Alli360, Forest, Opal, Fitlock, Pushscroll, TouchGrass и др.) гейтируют доступ к контенту через либо (а) простое ограничение по времени, либо (б) физическую активность, не связанную с типом полученной цифровой нагрузки. Ни один из найденных аналогов не подбирает разблокирующее задание **на основе типа** уже потреблённого контента таким образом, чтобы задание целенаправленно компенсировало вероятный когнитивный эффект именно этого типа контента.

**Суть технического решения (по шагам):**
1. Система регистрирует сигналы о взаимодействии пользователя с устройством/приложением (`SignalSource`: тип и длительность потреблённого контента, паттерн внутриигрового взаимодействия).
2. По зарегистрированным сигналам вычисляется вероятный тип когнитивной нагрузки (напр., длительная фиксация внимания на статичном контенте vs. частые переключения при скролле коротких видео) — сопоставление с предопределённым или обучаемым набором признаков.
3. На основе вычисленного типа нагрузки система выбирает — по таблице соответствия (`Skill.trigger` → `targetScales` → `exerciseParams`) — параметры компенсирующего упражнения: веса по типам упражнений, сдвиг сложности, целевые когнитивные шкалы.
4. Упражнение генерируется/подбирается по вычисленным параметрам и представляется пользователю как условие доступа: доступ к исходно запрошенному высокодофаминовому контенту блокируется вычислительно (на уровне приложения/ОС) до успешного завершения сессии.
5. Результат сессии обновляет цифровой когнитивный профиль пользователя (`CognitiveProfile.scales`), который используется для последующей калибровки будущих сессий (обратная связь).
6. (опционально, отдельный claim) Каждое такое правило соответствия хранится как версионируемая структура данных с указанием авторства и источников, что позволяет отследить и приоритет метода, и происхождение конкретного экспертного правила.

**Технический эффект (важно для п.3.1 — критерий "технического результата"):**
_(сформулировать вместе с поверенным; кандидат: "снижение вычислительной/пользовательской неэффективности типового гейтинга за счёт вычислительно управляемого подбора условия разблокировки, зависящего от предшествующего состояния взаимодействия пользователя с устройством" — нужно ИЗБЕГАТЬ формулировок эффекта в терминах "улучшение здоровья/когнитивных функций" — это уводит в медицинские claims, запрещённые терминологическим ограничением из раздела 2.4 профильного спека)_

**Отличия от найденного прайор-арта (см. раздел 2 выше):**
- US20150007307A1 и аналоги — гейтинг по факту выполнения задания, без связи типа задания с типом предшествующей нагрузки.
- WO2014107795A1, US20170046971A1, EP1301117B1 — адаптивная когнитивная тренировка по результатам самой тренировки, без входного сигнала о **внешнем** (по отношению к тренировке) цифровом поведении.
- Коммерческие "earn screen time" приложения — гейтинг через физическую активность, не через когнитивно-адаптивное задание, привязанное к типу контента.

**Известные ограничения / слабые места заявки** _(для честности при передаче поверенному)_:
- Компенсаторная гипотеза (что конкретный тип упражнения действительно компенсирует конкретный тип нагрузки) на момент написания **не подтверждена собственными данными** — см. `recovered-uncommitted/идея-проекта-для-команды.md`, раздел "Три отдельных трека R&D", пункт 2 ("Научный: компенсаторная гипотеза"). Это не блокирует патентную заявку (патент защищает способ, не требует клинического доказательства эффективности), но стоит явно обсудить с поверенным, не создаёт ли это риск для будущих claims об эффективности в маркетинге/заявке.
- Механизм собственно "вычислительной блокировки" на устройстве (App Store/Google Play review, iOS Screen Time API, Android Accessibility Service ограничения) — отдельный нерешённый инженерный риск (см. тот же документ, пункт 1 "Инженерный трек"), заявка может описывать способ безотносительно к тому, какой конкретно OS-API его реализует.

## 5. Открытые вопросы для патентного поверенного

1. Подтвердить финальный объём заявки (раздел 3.3) — одна широкая заявка vs. несколько узких.
2. Проверить формулировки на медицинские claims (обязательное ограничение из `2026-08-12-cognitive-profile-skills-platform-design.md`, раздел 2.4).
3. Оценить целесообразность подачи полезной модели (упрощённая, быстрая процедура в РФ) как промежуточного шага до полноценного изобретения.
4. Решить последовательность: подавать в РФ первой (приоритетная дата) → PCT в течение 12 месяцев (конвенционный приоритет), либо сразу PCT.
5. Оценить бюджет и обязательный полный поиск по базам ФИПС/WIPO PatentScope силами поверенного — открытый веб-поиск в этом документе такой поиск не заменяет.
6. Уточнить формат фиксации даты и содержания идеи как доказательства приоритета/авторства (нотариус, депонирование, git-история с подписанными коммитами — что из этого юридически весомо).
